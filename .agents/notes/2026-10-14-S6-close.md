## Lessons

- A large-ish first push (~10 MB of PNGs) over an OAuth-token HTTPS remote can
  die in the HTTP/2 framing layer before the real error surfaces; retrying over
  HTTP/1.1 reveals the underlying capability refusal (`workflow` scope). For
  pushes that legitimately touch `.github/workflows/`, go to the existing SSH
  key directly — it is the sanctioned fallback, not a workaround.
- A branch tip is not stable merely because a dispatch pinned it: master added
  a note to the carrier branch one minute after dispatch. Always re-check the
  branch tip immediately before deleting it — `git branch -d`'s merge safety
  check caught what a SHA-pinned assumption would have destroyed.
- The Pages enable is a repository-admin one-shot that must precede the
  push-triggered deploy for the first publication to succeed in one pass;
  doing it after acceptance but before the push avoided a failed first deploy.
- `Browser.grantPermissions` cannot be granted on an insecure origin — which is
  the behavior under test — so an insecure-origin regression invocation must
  keep `--en-url` on a secure origin and pass only `--insecure-url` separately.
