## Decisions

- **Merge ownership held**: the coordinator detached the primary checkout and the integration session alone merged and pushed (ordinary, non-force), per the working agreement; no conflict arose, so the §2.5 review-list path never fired.
- **Acceptance ledger sequencing, disclosed**: the sprint branch was cut from `origin/main` (`3e3ab7e`) before the sprint/epic docs materialized on local `main` (`cd05446..d18685f`), so the sprint doc never rode the branch and the accept-stage `active → acceptance` flip could not land in the acceptance commit. The verdict was therefore read from the acceptance record itself (pass), not inferred from state, and the ledger was finalized `merged` with `merged-commit: ae274a3` (branch tip) in this close-out act on main.
- **Arrears final check clean**: branch-changed paths vs `doc_sync_map` keys intersect empty (runtime.py/adapters.py pinned unchanged; scripts untouched) — no row fired; truth docs rode same-commit in Wave 2 by design.
- **Close-out push**: this close-out commit is pushed by the master as the sprint's integration tail (ordinary push; S14 precedent — close-out docs live on origin).
- **Pages-deploy observation**: the Pages workflow did not trigger for `1bbef65` (it ran for `3e3ab7e` only); `check_site` passed on merged main, so no action taken — recorded as an observation, not a gap.

## Lessons

- **Cut sprint branches from the local main tip, or push master docs before dispatch.** Because the branch was cut at `origin/main`, the sprint plan and E15 roadmap were absent from the worktree; the review and acceptance both had to read them from main via `git show` (recorded in their notes). It worked, but it is a seam — next sprint: dispatch only after master doc commits are pushed, or branch from local main.
- **Orca CLI reuse mechanics**: `--terminal` cannot combine with `--agent` (reuse implies the existing agent); reusing a terminal for a task created in another workspace requires an explicit `--worktree id:<full-id>` selector; `orca worktree rm` removes the worktree and its branch in one act (no separate `git branch -d` — a follow-up delete races and reports "not found").
- **The freeze acceptance pattern works as designed**: the D82-style byte pin plus stop-and-ask escalation kept a whole sprint honest without firing once; the two disclosed family constraints (identity keyed on the ticket reference; one reference = one governed dispatch → `OPERATION_CONTENT_CONFLICT`) are exactly the kind of finding a third family should surface rather than absorb.
