## Lessons

- The acceptance harness hit five shape errors before any product conclusion
  — all probe-side, all diagnosable from the public surface: rejected
  commands are receipt dicts keyed `code` (never `reason`), a `contract =
  None` attribute is malformed by design (only an *absent* descriptor is
  legacy), result-mismatch quarantine parks the **work** in
  `needs_attention` while the operation stays `outcome_unknown`, revoke
  denials return `AUTHORITY_DENIED` dicts rather than raising, and
  `ReadOnlyInspector.work_detail` lists operations under `id`. Same class as
  the W1 reviewer's 13 probe iterations: read the exact API shape before
  writing the assertion, and treat every first-run failure as a hypothesis
  about the probe first.
- Re-running a demo's printed `inspect` command needs `shlex.split` — naive
  whitespace splitting keeps the quotes inside the `--db` token, and SQLite
  silently creates a fresh empty database (observed as `Unknown work`),
  which can masquerade as a product failure.
- A verifier that signals rejection via `SystemExit` (script-style `FAILED:`
  exits) cannot be mutation-tested with `except Exception` — catch
  `BaseException` or the first rejection terminates the harness.
- The pre-merge consolidation pattern (soft reset to main + scoped combined
  commits regrouped by wave, with `^{tree}` byte-equality as the proof and
  preservation branches/tags for the original history) pays same-commit
  doc-sync arrears in the release history without rewriting owner branches —
  reusable for any future D47-class letter gap that reaches integration.
