◆ Governed Work Runtime

English

让 Agent 自主规划，让每次业务行动都有依据。

面向长期业务工作的持久运行时：Agent 提议行动，规则决定能否执行，证据证明是否完成。

Pre-alpha 状态：本地参考原型 · Python 3.9+ · Apache-2.0 · 零运行时依赖

运行演示 在 GitHub 查看
01 · 持久化状态

工作义务、等待、命令回执与逻辑操作全部落盘至 SQLite，跨越进程重启与会话中断。

02 · 准入与证明分离

策略规则在外部调用前拦截不合规提议；完成闭环前必须匹配经核验的证据。

03 · 同键崩溃恢复

外部受理后若进程崩溃，重启后按原业务键找回受理记录，绝不盲目重复提交。

为什么需要 Work 运行时

业务工作比对话活得更久

业务任务可以跨越多次对话：计划会修订，批准可能数天后才到，一次超时的调用可能已经在外部系统创建了真实申请。本项目把必须履行的责任、约束与证据保存在持久的 Work 中。

工作比会话活得更久

计划会变、批准会迟到、超时的调用可能已经产生真实效果。运行时把义务绑定在工作上，而不是绑定在某个计划步骤上。

决策被持久记录

命令、回执、证据、等待与逻辑操作全部持久化。重启后通过原业务键找回受理记录——不重复提交，也不丢外部效果。

规则决定准入，证据证明完成

策略决定提议能否被接纳，核验后的证据决定工作能否被判定完成。Agent 选择策略，运行时守住已接受的规则。

  • 工作 vs 计划 删掉一个计划步骤，不能免除它的审批要求。
  • 命令 vs 操作 vs 尝试 响应丢失与重试保留原业务身份。
  • 执行 vs 证明 没有匹配证据的完成调用，不能确立业务结果。

架构

从提议到证明的一条可问责路径

  1. 提议者

    Agent 提议下一步行动，不直接把工作改成“已批准”或“已完成”。

  2. 版本绑定命令

    命令按内容去重，按绑定的合同修订号校验；回执不可变，事件只追加。

  3. 策略门

    规则决定接纳或阻断每条提议——例如缺少 E05 特别批准。被拒绝的决定同样被记录，绝不静默丢弃。

  4. 持久操作

    每个外部效果归属唯一的逻辑操作。等待、过期与不确定结果是显式的持久状态。

  5. 适配器 / 效果

    外部系统通过声明的 Adapter 接口接入。结果不确定时查询原操作解决——绝不盲目重发。

  6. 回执 / 证据

    完成需要经过核验的证据：运行时先匹配回执与证据，才记录 SUCCEEDED。

阻断（如缺少批准）、被拒命令与干预都作为持久决策记录。外部提交后响应丢失时，恢复流程按原业务键重新查询原操作——效果恰好找回一次，或升级人工处理，绝不盲目重放。语义详见 RFC-001 核心语义 与 RFC-003 运行时协议。

演示

看它从一次真实崩溃中恢复

示例 示例演示 —— 以下六步是 python3 -m work_runtime demo 的真实输出记录，不是运行中的 Python 引擎，也不是在线 Agent。点击任意阶段卡片或使用按钮即可查看对应的持久状态变化。

  1. 提议被阻断

    1. Agent 提议提交 → 被 E05（缺少特别批准）阻断

  2. 持久等待

    2. 工作进入持久等待，Agent 无需持续在线

  3. 批准到达

    3. 财务批准当前版本内容 → 提交意图被接受

  4. 受理后崩溃

    4. 模拟 OA 受理后，工作进程在保存响应前直接退出（真实进程崩溃）

  5. 同键恢复

    5. 重启 Runtime → 查询原操作 → 找回已有 OA 受理记录

  6. 证据完成

    6. 证据齐备，验收完成 → SUCCEEDED；外部申请数量：1

演示会创建全新的临时数据库，启动独立工作进程，并在外部服务提交后故意终止它。末行数字由外部数据库独立核对：受理申请恰好为 1。

浏览持久历史：本地只读 GUI

python3 -m work_runtime ui-demo

ui-demo 通过真实运行时命令播种五项报销工作并启动本地只读运维查看器，每项工作对应一种典型的治理与恢复状态：

wait-1 waiting

在 E05 审批规则上持久等待；已提交的审批证据待核验，早期被拒提议作为历史决策保留。

uncertain-1 needs_attention

外部 OA 已受理但响应丢失，权威查询不可用时升级为需关注，外部真实申请完整保留。

transfer-1 active

负责人移交至 delegate 使原准备意图失效；新负责人重入同一逻辑操作并完成确认。

succeed-1 closed · succeeded

外部确认回执与核验证据齐备，工作以 succeeded 结果完成验收关闭。

cancel-1 closed · cancelled

不确定提交先经对账确认为已生效，取消闭环显式确认并保留外部真实效果。

快速开始

三条命令体验真实崩溃恢复

git clone https://github.com/WayJ/governed-agentic-work-runtime.git
cd governed-agentic-work-runtime
python3 -m work_runtime demo

需要 Python 3.9 或更高版本。无需模型 API Key、无需凭据、无第三方运行依赖。每次演示运行都创建新的临时目录，绝不覆盖之前的结果。

同一检出中的更多演示

  • python3 -m work_runtime publish-demo 签名证据守住发布关口：HMAC 信封、篡改拒绝、超时后同键恢复。
  • python3 -m work_runtime intervention-demo 所有权转移、不确定外部效果的取消、显式策略迁移。
  • python3 -m work_runtime adoption-demo 静态 SOP 规则卡检查，加上经第三个适配器的真实文件发布。
  • python3 -m work_runtime ui-demo 播种五工作样例库并启动本地只读运维界面。
