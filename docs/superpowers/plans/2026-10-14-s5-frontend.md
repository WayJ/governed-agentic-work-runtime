# S5 Frontend/CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the S5 wave-1 frontend/CLI slice: offline bilingual browser assets consuming the D25-pinned read-only API, a real-command five-work seed (`ui_demo.py`), `ui`/`ui-demo` CLI commands with lazy backend imports, asset packaging and honest installed verification, and user docs.

**Architecture:** One new module `work_runtime/ui_demo.py` owns the real-command seed (`seed_ui_demo`), the documented `UnavailableLookup` composition wrapper, the shared serve loop (`serve_ui`) and `run_ui_demo`; `work_runtime/cli.py` gains `ui --db <existing> [--port N]` and `ui-demo [--directory DIR] [--port N]` with backend imports deferred into the command branches so every prior command keeps working without backend files. `work_runtime/web/{index.html,app.js,app.css}` are dependency-free vanilla assets rendered exclusively through `textContent`. `pyproject.toml` ships `web/*`; `scripts/verify_install.py` gains an always-run packaged-assets stage and a backend-conditional HTTP stage that skips loudly (never silently) when the read-only backend is not assembled; CI is unchanged (existing steps already cover the suite and verifier).

**Tech Stack:** Python >= 3.9 standard library only (`tempfile`, `argparse`, `sqlite3` for independent test parses), `unittest`, vanilla HTML/CSS/JS with no CDN, framework, build step or network access.

**Spec:** `docs/superpowers/specs/2026-10-14-s5-gui-design.md` (design + D25 ratification, which **overrides** the builder report where they differ), `docs/superpowers/sprints/2026-10-14-S5-plan.md` Wave 1 frontend story + DoD, `docs/superpowers/plans/2026-10-14-s5-supervision.md` Task 2 + Review Focus, `.agents/notes/2026-10-14-S5-open.md`, `.agents/notes/2026-10-14-S4-close.md` (lessons), `AGENTS.md`.

## Pinned contract (decisions the implementer cannot choose)

### Seed fixture (D25 B4 + corrections)

- `seed_ui_demo(directory=None) -> str`: fresh `tempfile.mkdtemp(prefix="governed-ui-", dir=directory)` containing one `runtime.sqlite` + one shared `oa.sqlite`; returns the runtime DB path. Grants `intervention_grants()`; default `ExpensePolicy()` (no registry — no migration in the fixture).
- Five works, each `document(amount=120000, limit=100000)` over-limit so E05 applies, distinct `document_id` `EXP-UI-001..005` and invoice id `INV-UI-001..005` (FakeOA enforces external invoice uniqueness):
  - `wait-1`: `initialize` → `prerequisites(approval=False)` → proposal rejected `REQUIREMENT_UNSATISFIED` (persisted historic blocker) → `register_wait` on the actual E05 requirement id (deadline `2000000000`, owner `finance`) → finance records the approval proof but it stays `pending_verification`. Final: status `waiting`, E05 applicable/pending, one waiting wait, one pending evidence.
  - `uncertain-1`: full prerequisites → proposal accepted → `dispatch` with `FakeOA(timeout_after_commit=True)` → `outcome_unknown` while the OA store retains the accepted effect → `reconcile(op, UnavailableLookup(oa))` → `NO_AUTHORITATIVE_RESULT` + work `needs_attention` + `ReconciliationRequired` event. (A mere post-commit timeout alone must leave the work `active` — D25 correction.)
  - `transfer-1`: prerequisites → agent proposal accepted → `transfer_owner` agent→delegate → prepared intent invalidated `OWNERSHIP_TRANSFERRED` → delegate re-proposal readmits the SAME operation → `dispatch` → `confirmed_succeeded`. Final: owner `delegate`, status `active`.
  - `succeed-1`: prerequisites → proposal accepted → `dispatch` → `confirmed_succeeded` → `request_completion` → `closed/succeeded` with `completion`.
  - `cancel-1`: prerequisites → proposal accepted → `dispatch` with `timeout_after_commit=True` → `request_cancel` → `reconcile` with the REAL `FakeOA` (recovers `external_id`) → `finalize_cancel` with the exact acknowledged operation → `closed/cancelled`; `completion.acknowledged_operations[0].external_id` equals the recovered id; the OA effect stays (accepted, not reversed).
- `UnavailableLookup`: documented composition wrapper exposing `lookup(key) -> None` over the real adapter (the committed effect stays in the wrapped store); reconcile therefore sees no authoritative result. Never edits `FakeOA`.
- Final accepted count in the shared OA store: exactly 4 (uncertain/transfer/succeed/cancel, one each).

### CLI serve loop (D25)

- `serve_ui(db_path, port=0, server_factory=None)`: validates `0 <= port <= 65535` and that `db_path` is an existing file — bounded stderr message + `SystemExit(2)` on failure, both BEFORE any backend import; then resolves the server via `server_factory` or lazy `from .ui_server import make_ui_server` (`ImportError` → bounded "UI backend not available" + exit 2); startup exceptions → bounded `cannot start UI` message + exit 2 (no traceback); on success prints `http://127.0.0.1:<actual port>/` with `flush=True`, serves until `KeyboardInterrupt`, then `server_close()` and a clean normal exit.
- `run_ui_demo(directory=None, port=0)`: seeds, prints a short seeded summary (five work ids, store path, inspect command), then `serve_ui`.
- `cli.py`: `ui` (`--db` required, `--port` int default 0) and `ui-demo` (`--directory`, `--port` int default 0) subcommands; imports from `.ui_demo` inside the command branches only — `import work_runtime.cli` must never transitively import `work_runtime.ui_server`.

### Browser assets (design "Browser experience" + D25)

- Static whitelist files only: `index.html` (skeleton, `app.css` link, `defer app.js`, no inline script/style), `app.js`, `app.css`. Brand "Governed Work", clean light business theme.
- Consume exactly: `GET /api/summary`, `GET /api/works?limit&offset`, `GET /api/work?id=`, `GET /api/events?work_id=&after=&limit=` per the D25 DTO (decimal-string `seq/version/state_version/revision/deadline/cursors`, `*_raw` verbatim text fields, `commands` sorted by decision version then actor/id, dynamic status maps).
- ALL stored data rendered through `createElement`/`textContent`; `innerHTML` never used for data; `external_id`/source strings are text, never links; `JSON.parse` is applied only to the top-level response envelope — `*_raw` string values are never parsed; string numbers are never routed through `Number()`.
- States: loading/empty/error/disconnected; manual refresh always works; 5 s polling with explicit pause/resume; single refresh epoch + selected-id guard so stale responses never overwrite newer state or another work's detail.
- Five metric tiles with visible definitions: open works, closed succeeded, closed cancelled, uncertain operations (dispatched + outcome_unknown), pending evidence (`pending_verification`).
- Detail sections: overview (contract/goal/waits/cancellation banner independent of presentation status; cancelled closure explains the acknowledged retained effect), requirements (current applicability/fulfillment, explicitly separate from historic decision blockers), evidence, operations + attempts, persisted command decisions (admissions note), keyset-paginated event timeline (`after` cursor passed unchanged, has_more → load more), exact raw documents/closure text.
- Bilingual EN/中文 (browser language default via `navigator.language`, explicit toggle); keyboard: list buttons focusable, ArrowUp/Down list navigation, tabbed detail sections with roving focus; responsive single-column narrow layout with no horizontal overflow (`overflow-wrap: anywhere` for ids/digests).

Docstring stage list updated to match. No prior stage changes.

## Review Focus

1. **Stale response races** — a slow `/api/work` for a deselected work overwriting the newly selected one, or an out-of-order poll clobbering a manual refresh: epoch + selected-id guards must drop stale payloads; pinned by Task 3 lifecycle tests (selection guard) and assembled browser review (pending).
2. **Precision loss on big integers** — `state_version`/`seq`/`revision` routed through `Number()` or raw fields re-parsed: strings must reach `textContent` untouched; pinned by Task 4 asset rules + assembled precision fixture (pending), enforced now by code review against the pinned contract.
3. **Prior CLI breakage through eager backend imports** — `import work_runtime.cli` (or any prior subcommand) failing once `ui_server` is referenced at module top: pinned by Task 3 `sys.modules` isolation test, which must keep passing after the backend is assembled.
4. **Seed fabricating state via SQL or deleting user data** — direct `UPDATE works` or wiping an existing directory: pinned by Task 2 hygiene tests (sentinel survives, distinct folders, real command evidence: events/commands tables populated, OA counts exact).
5. **Verifier skip masquerading as pass** — UI HTTP stage silently green with no backend: pinned by Task 5 requiring an explicit `SKIPPED` line and a final summary that discloses skipped stages; the assets stage itself cannot skip.
