# S9 Core — Accepted-Evidence Collision Prevention and Recovery Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Coordinator owns dispatch; no extra workers, no merge/push, no local approval UI (user opted out; blocking decisions go through Orca `ask`).

**Goal:** Implement ratified D38–D42 in `work_runtime/runtime.py`: prevent accepted-source imports of stored operation ids at intake (D39), and resolve existing poisoned stores by persisting the actual accepted external result with an exact conflict snapshot instead of dying on the proof INSERT (D40/D41) — pinned by meaningful RED/GREEN tests in both policy families, with same-commit boundary docs.

**Architecture:** One new persisted rejection branch in `_receive` after the unchanged authority and old-row dedup/conflict branches, guarded by a per-intake recomputed union of loaded policies' accepted sources; one pre-check in `_resolve`'s accepted branch that swaps the proof INSERT for an additive nine-field `proof_conflict` on the operation plus an eleven-field `AcceptanceProofConflict` event (replacing `OperationResolved` on that path only). Nothing else in the command/recovery surface changes; schema stays `1`.

**Tech Stack:** Python>=3.9 stdlib (json/sqlite3/uuid already imported), SQLite, standard-library `unittest`, existing `FakeOA`/`FakePublisher` for real effect counts, real `subprocess`/`os._exit` children for crash tests.

## Global Constraints

- Ownership: `work_runtime/runtime.py`, `tests/test_accepted_evidence_collision.py` (+ focused existing-test additions only if unavoidable), `docs/runtime-boundaries.md` **same commit** as each runtime change, current `docs/verification.md` / `docs/interventions.md` / `docs/evidence-revocation.md`, this plan and `.agents/notes/2026-10-15-S9-core-report.md`. No policy/adapters/schema/inspection/web/CLI/demo/install/README/site/AGENTS/roadmap/sprint/acceptance/debt-tracker edits. TD-1 stays open; integration repays with the merge hash.
- Python>=3.9, zero runtime dependencies, stdlib `unittest`, schema stays `1`.
- Precedence in `_receive` (unchanged order, one new step): shape/identity → source+kind authority → existing-row dedup resend / `SOURCE_EVENT_CONFLICT` → **`OPERATION_ID_RESERVED`** → insert pending candidate. Cache/fingerprint/version mechanics and `_replay_denial` untouched.
- Reservation predicate (D39): fires only when `event_id` exactly matches a stored operation id AND the actor is the accepted source (nonempty string) of **any** currently loaded policy version — union recomputed **per intake** from `self.policies.values()`, never cached, never assuming a fallback or policy-object immutability. Applies across works, across proof kinds, permanently. Conservative over-block (an accepted source importing *another* work's operation id) is intended and documented. Unrelated sources and fresh-id imports stay valid.
- Rejection receipt: `{"decision":"rejected","code":"OPERATION_ID_RESERVED","observed_state_version":<current>,"blockers":[<matched operation id>]}`, persisted like every rejected receipt; replays verbatim under the stored command id while current authority holds.
- Conflict detection (D40): in `_resolve`'s accepted branch, exact PK probe `SELECT work_id,fingerprint,body FROM evidence WHERE source=? AND event_id=?` with `(accepted_source, operation id)` **before** the INSERT, inside the same transaction as all other resolution writes.
- `proof_conflict` on the operation: **exactly nine fields** — `source`, `event_id` (collision PK strings), `evidence_id`, `evidence_kind`, `evidence_status` (body-derived; nonempty string else `null` — missing/wrong-type/non-object bodies degrade, nothing coerced), `evidence_work_id`, `evidence_fingerprint` (SQL columns, verbatim), `external_id` (actual validated adapter result), `document_digest` (the operation's digest) — never the candidate's `data.digest`, never an ambiguous digest. Invalid JSON in the body is a corrupt store: repair out of scope (the parse error propagates and rolls back).
- Conflict resolution (D41): persist actual `confirmed_succeeded` / `dispatch_state="finished"` / `external_id` / `attempts[-1]["status"]`; never overwrite, delete, revoke or convert the conflicting candidate (its SQL identity, fingerprint and body stay byte-identical); set `needs_attention` **only when the work was not closed** — closed `status`/`outcome`/`completion` stay byte-stable even in custom legacy fixtures. One transaction, one work version bump, one event `AcceptanceProofConflict` with **exactly eleven fields** (the nine snapshot fields + `operation_id` + `work_was_closed`), replacing `OperationResolved` on the conflict path only; normal resolution unchanged.
- Settled-op idempotence: after conflict resolution, repeated `reconcile`/`recover` makes **no writes to that operation or its conflict event and no adapter execute/lookup for it**, while `recover` may still verify/expire other records and must reach later operations. No new completion blocker; trusted accepted imports keep their existing authority; a new-event replacement proof works through current configuration; cancellation acknowledges the real confirmed effect.
- Tests: fresh baseline 702 (skipped=1) verified; meaningful RED before code for prevention (both families), legacy conflict resolution, liveness and real-effect families; legacy stores built by **direct SQL with the canonical pre-fix `_receive` row shape from accepted original inputs, clearly labelled, no product bypass**. No faked external calls or proof statistics; crash tests use real exception injection and a real `os._exit` child.
- DoD: full suite, all five configured gates (`check_docs.py`, unittest discover, `demo`, `compileall`, `check_site.py`), five demos (`demo`, `publish-demo`, `intervention-demo`, `adoption-demo`, `revocation-demo`), 14-test rehearsal (`python3 -m unittest examples.rehearsal.test_queue_adapter`), and actual `python3 scripts/verify_install.py` — installer unchanged (test-only use acceptable). Report exact counts/skips.

## Review Focus

1. **Exact resend of a pre-fix poisoning payload after the fix** must hit the old-row dedup branch (accepted, current status) — not `OPERATION_ID_RESERVED`; changed content stays `SOURCE_EVENT_CONFLICT`. Pinned in Task 3 (precedence) and Task 1 (order of branches).
2. **Stored `OPERATION_ID_RESERVED` replayed after authority loss** must return a fresh unpersisted `AUTHORITY_DENIED` (replay reauthorization unchanged) — else stale authority survives in replays. Pinned in Task 3.
3. **Conflict resolution on a custom closed work** must not reopen or overwrite `closed`/outcome/completion — the F3 guard; a silent `needs_attention` write would corrupt closed history. Pinned in Task 2.
4. **Repeated recovery after settlement** must be operation-scoped: zero writes/calls for the settled op and its event, while other records still verify/expire and later operations still dispatch — an unscoped "whole-store byte equality" claim would false-fail, an unimplemented one re-executes effects. Pinned in Task 3.
5. **Registry/policy reconfiguration** (renamed accepted source across loaded versions; policy-object mutation after init) must move the union on the next intake — a frozen union under-blocks after reconfiguration and over-blocks retired sources forever. Pinned in Task 1.
