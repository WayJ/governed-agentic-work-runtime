**Goal:** Ship the ratified S12 wave 2 (stories 5–6): a deterministic
no-credentials `publication-demo` harness proving the whole D54–D66 story
end to end, its CLI entry point, one installed module+console verifier
stage, the docs wave (sop-authoring.md publication-section rewrite incl.

bilingual README entries) — with no new global gate and no W1-core change.

**Architecture:** A new `work_runtime/publication_demo.py` drives the frozen
W1 core (`work_runtime/publication.py`, `FilePublisher.read_validated`)
through its public API exactly as the independent review's probes did:
lint prologue → governed work → blocked proposal → tampered/valid signed
approvals → response-loss dispatch → restart reconcile → runtime-written
accepted proof → completion → D66 doctored-card conflict → fail-closed
loader checks → approver-key rotation. Tests and `scripts/verify_install.py`
read the real SQLite store and artifact directory, never trusting stdout.

**Tech Stack:** Python ≥3.9 standard library only, `unittest`, real SQLite +
real filesystem directories, zero runtime dependencies.

## Review focus (input classes the spec implies; each pinned by a test)

1. **Secret echo** — approver secrets/signatures leaking into demo output →
   planted-marker test patches `secrets.token_bytes` and asserts the marker,
   its hex, and a locally computed envelope signature never appear (Task 1).
2. **Winner-artifact mutation** — conflict or rotation silently rewriting the
   committed artifact → byte-identity asserts in-demo plus test/verifier
   re-derivation of digests and the doctored goal's absence from the stored
   bytes (Tasks 1–2).
3. **Forged acceptance** — an `accepted` proof that is not runtime-written →
   verifier requires source `sop-store` (absent from grants), `event_id` =
   the operation id, digest-bound with the receipt's `external_id` (Task 2).
4. **Absent-vs-corrupt confusion** — the loader conflating or falling back on
   absent version / tampered file → demo asserts the two bounded messages
   differ; tests pin both (Task 1).
5. **Old-key revival** — a retired envelope accepted after rotation or
   rotation writing history → in-demo six-table + artifact byte-identity
   around the refusal; verifier pins table counts and the refusal receipt
   (Tasks 1–2).
