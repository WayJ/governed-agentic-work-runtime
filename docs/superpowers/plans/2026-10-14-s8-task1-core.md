# S8 Task1 — Evidence Revocation Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Coordinator owns dispatch; no extra workers, no merge/push.

**Goal:** Deliver the ratified D33–D37 trusted-local `revoke_evidence` command and permanent `revoked` proof status in `work_runtime/runtime.py`, fix the D-1 unbound closed-work guard, and pin both with meaningful RED/GREEN tests plus synced docs.

**Architecture:** One new command kind routed beside `record_evidence` (before the closed-work guard), a body-status UPDATE that never deletes rows, requirement/wait dispositions computed by diffing the pure `_evaluate` re-run, a `_replay_denial` branch, and an additive `evidence_status` on new-command resend receipts. Schema stays `1`; no policy edits.

**Tech Stack:** Python>=3.9 stdlib, SQLite, standard-library unittest, existing `FakeOA`/`FakePublisher` for real effect counts.

**Spec:** [Ratified design D33–D37](../specs/2026-10-14-s8-evidence-revocation-design.md) (supersedes review recommendations), [S8 sprint](../sprints/2026-10-14-S8-plan.md), [S8 plan Task1](2026-10-14-s8-revocation.md), [design review](../../../.agents/notes/2026-10-14-S8-design-review.md), [RFC-001](../../../docs/RFC-001-core-semantics.md), [RFC-003](../../../docs/RFC-003-runtime-protocol.md), AGENTS.md.

## Global Constraints

- Payload exactly `{source, event_id, reason}` nonempty strings; malformed fresh commands raise `CommandError` with rollback. Codes exactly: `EVIDENCE_UNKNOWN`, `EVIDENCE_SCOPE_MISMATCH`, `EVIDENCE_ALREADY_REVOKED`, `EVIDENCE_NOT_REVOKABLE`; authority failures `AUTHORITY_DENIED`; stale `STATE_VERSION_CONFLICT` (existing envelope).
- Authority: `work.intervene` admin, or the work's currently configured source for the **stored proof kind** holding `evidence.revoke`. Owner/`work.manage`/`evidence.write` alone never revoke. Admin still obeys scope/status/version.
- Rejected unknown-proof commands (fresh and replay) use only the conservative preliminary check: admin, or `evidence.revoke` + current-source-membership in the pinned policy's `evidence_sources` values.
- Accepted receipt: `{command_id, decision:"accepted", result_state_version (the single new version), evidence_id, evidence_status:"revoked", prior_status}`.
- Event `EvidenceRevoked` fields exactly: `actor, evidence_id, source, event_id, kind, prior_status, reason, work_was_closed, completion_cites_evidence, affected_requirements, wait_dispositions`. `affected_requirements` = actual id/before/after applicability+fulfillment diffs (never hard-coded); `wait_dispositions` = `{id, prior_status, status, disposition}` for every stored wait, disposition `"unchanged"` or the new status.
- Proof row permanence: UPDATE only `status` → `"revoked"`; `id/source/event_id/kind/data` and the source-event fingerprint column byte-preserved; rows never deleted. Old command receipts, completion snapshots, outcome and confirmed-effect records immutable.
- Eligible statuses: `pending_verification` and `verified` only. Revocation allowed during active cancellation and on unbound works; closed works stay closed (no reopen, no `needs_attention`).
- No eager wait/operation mutation in revoke: no deadline reset, no cancelled-wait resurrection, no held write. Dispatch/recover holds with `REQUIREMENT_UNSATISFIED`, zero attempts/external calls; replacement verification re-admits the same business key; in-flight/unknown/confirmed ops keep attempts/key/result/external_id.
- verify_pending/migration/restart/dedup-resend/old-command replay never revive a revoked row. New-command resend receipt adds current `evidence_status`; changed content stays `SOURCE_EVENT_CONFLICT`; original cached receipts verbatim.
- D-4 (privileged accepted-source collision) stays TD-1 deferred — not fixed, not claimed.
- No schema/table, policy, protocol, adapters, CLI, demo, verifier, reader, web, README, AGENTS, roadmap or sprint-ledger changes. Test-owned subclasses/private-hook overrides are allowed; no new public fault parameter.
- Doc sync owed by `runtime.py`: `docs/runtime-boundaries.md`; also `docs/interventions.md`, `docs/verification.md`, new `docs/evidence-revocation.md`.

## Review Focus

- Cached **accepted** revoke replayed after the source loses `evidence.revoke` (or admin loses `work.intervene`) must return fresh unpersisted `AUTHORITY_DENIED` while the stored receipt stays byte-intact — the `_replay_denial` branch is the silent-failure edge.
- Multiple sufficient proofs plus unrelated waits must not produce false `affected_requirements` entries, wait resurrect/deadline resets, or eager operation holds.
- Unbound finalize → late verify/recover/revoke must keep `closed` with byte-stable completion (D-1/D-2); persisted pre-fix erroneous snapshots are not rewritten (documented limit).
- Revoked accepted proof of a confirmed op: re-propose/dispatch/reconcile must not re-execute or regenerate the proof; uncertain acceptance still reconciles to exactly one retained effect.
- Closed-work correction must distinguish current invalidity (requirements + event) from the untouched historical completion and retained external effects; cancellation completion never invents evidence citations.
