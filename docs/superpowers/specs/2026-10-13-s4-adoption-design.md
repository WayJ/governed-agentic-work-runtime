# S4 adoption and authoring design

## Intent

Make the runtime useful to a new contributor: lint a reviewable SOP package, implement a third adapter without changing lifecycle internals, and exercise that adapter through an inspectable no-credentials harness. Master chooses this next slice from E4 after S3 acceptance. User explicitly authorized continuous autonomous sprints on 2026-10-13, no between-sprint approval wait. Preserve Python>=3.9, stdlib only, all273 tests and all earlier demos. No Runtime/Policy lifecycle modifications, no natural-language compiler, no proof of business truth or production authorization.

## Static SOP authoring

`work_runtime/authoring.py`: `lint_sop(value) -> list[dict]`, deterministic diagnostics `{code,path,message}` sorted by JSON pointer then code; `sop_digest(value) -> str` only for lint-clean JSON-native input, canonical SHA256, invalid raises ValueError. Pure functions, no filesystem/runtime calls, no coercion, no secret data echoed. Reject non-JSON native types/nonfinite floats/cycles/deep invalid inputs predictably, no raw RecursionError/UnicodeEncodeError leakage. Lint failure is a result, not a crashing stack trace.

Pin a small versioned JSON rule-card schema rooted at exactly `schema_version`, `policy`, `defaults`, `facts`, `collections`, `rules`, `advice`. schema_version integer1 (not bool). Policy exact id/version/goal/source/scope/capabilities; identity/text nonempty strings, source exact document/version/section nonempty strings, capabilities unique nonempty strings. Defaults exact unknown/conflict/exemptions/migration values block/escalate/forbidden/explicit. Facts unique nonempty fact IDs. Collections exact id/version/completeness/allow_empty (three nonempty strings, last bool), unique IDs distinct from facts/rule IDs. Rules required exact id/source/modality/type/scope/trigger/depends_on/requirement/deadline/evidence/unknown/conflict/exemption/migration. Rules source same shape as policy source; modality must/forbidden, type state/action/history; explanatory strings nonempty; scope must name document or a declared collection; depends_on unique references to declared facts/collections/rule IDs; unknown block, conflict escalate, exemption forbidden, migration explicit. Evidence exact kind/source/subject/version all nonempty strings (declared provenance, not authenticated facts). Deadline either goal or one declared capability. Advice list of nonempty strings, kept separate and cannot become mandatory rules. Unknown fields rejected. Rules/facts/collections may be empty where meaningful, but at least one mandatory rule required for valid package. Cycle detection over rule-to-rule dependencies; undeclared references, duplicate IDs and deadline capabilities are diagnostics. No arbitrary expression evaluation or semantic natural-language consistency checking; lint-clean means structural review readiness only, not Runtime executable or published authority. `sop_digest` ties manual review to exact submitted content; this sprint does not implement authority approvals or immutable publication store.

Developer publishes valid expense/publishing rule-card examples and invalid bounded fixtures under `examples/sop/`, JSON only; dates/paths do not confer policy authority. CLI consumer later adds `lint-sop <path> --json` with stable JSON diagnostics, human display otherwise; exit0 clean/1 lint defects/2 malformed file or CLI usage. Duplicate JSON object keys must not be silently accepted by CLI loader. Linter API rejects invalid Python shapes; loader errors never output input contents/secrets. Clean CLI emits digest plus clear static-only limitation. Explain that textual predicates/source assertions still require a business publisher and engineered Policy implementation. Real external author feedback remains uncollected; independent Claude guide-only exercise is an agent rehearsal, not fabricated human validation.

## Filesystem third adapter

`work_runtime/file_adapter.py`: `FilePublisher(directory)` with actions content.publish, idempotency scope directory+key, lifetime-of-directory retention, lookup authoritative for committed by-key artifact, no additional document-content uniqueness promise (uniqueness empty tuple). Same Runtime/PubPolicy, different real side effect: actual immutable JSON artifact on local disk. No SQLite in adapter and no lifecycle edits.

Strict nonempty-string key and digest(document)==content_digest; document detached canonical JSON-native snapshot, malformed/mismatched input ValueError before any artifact. Hash key to a safe fixed basename; never use caller key/document.id as a path. Durable committed artifact includes original key, content digest, document and accepted receipt with stable nonempty external_id. `execute` samekey/samecontent returns identical receipt; samekey/differentcontent raises ValueError without overwriting; `lookup` missing returnsNone, malformed/corrupt artifact raises bounded ValueError (Runtime will retain unknown outcome), wrong-key/digest/result content is never accepted. Query reconstructs/validates artifact contents, including actual stored document digest, not just a receipt field.

Publish through atomic non-overwriting file creation using a staging file and exclusive commit (builder pins portable strategy). A crash before commit can leave only ignorable staging; after commit/query returns same receipt and exactly one committed artifact. Stage fsync before commit; declare directory sync/power-loss/platform boundaries honestly. Existing committed files never overwritten. Independent processes racing samekey must produce one committed artifact and stable result or documented retryable contention, no partial accepted file. Real conformance mixin adopter + restart/key-mismatch/corruption/path traversal/concurrent duplicate tests with actual filesystem enumeration and JSON contents. Single coordinator Runtime remains unchanged; adapter uniqueness does not imply distributed Runtime exactly-once or external fencing. Root directory trusted-local, no hostile filesystem/symlink security claim.

## Non-goals and acceptance boundaries

No HTTP/LLM provider dependencies, tenant auth, arbitrary DSL evaluation, semantic SOP proof, signed policy publication, cross-domain runtime registry, compensation/revocation/distributed leases. These remain explicit roadmap follow-ups. Acceptance measures actual lint diagnostics and exact content digest, third adapter conformance and one real artifact across uncertain-effect recovery, installed module+console effect proof, unchanged Runtime/Policy baseline, truthful docs and independent guide rehearsal. Every claim maps to fresh commands and source outputs; no cannedstdout-only verification. Root master makes routine decisions; only external blockers need user attention.
