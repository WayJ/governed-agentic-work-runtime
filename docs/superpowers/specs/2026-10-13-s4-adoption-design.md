# S4 adoption and authoring design

## Intent

Make the runtime useful to a new contributor: lint a reviewable SOP package, implement a third adapter without changing lifecycle internals, and exercise that adapter through an inspectable no-credentials harness. Master chooses this next slice from E4 after S3 acceptance. User explicitly authorized continuous autonomous sprints on 2026-10-13, no between-sprint approval wait. Preserve Python>=3.9, stdlib only, all273 tests and all earlier demos. No Runtime/Policy lifecycle modifications, no natural-language compiler, no proof of business truth or production authorization.

## Static SOP authoring

`work_runtime/authoring.py`: `lint_sop(value) -> list[dict]`, deterministic diagnostics `{code,path,message}` sorted by JSON pointer then code; `sop_digest(value) -> str` only for lint-clean JSON-native input, canonical SHA256, invalid raises ValueError. Pure functions, no filesystem/runtime calls, no coercion, no secret data echoed. Reject non-JSON native types/nonfinite floats/cycles/deep invalid inputs predictably, no raw RecursionError/UnicodeEncodeError leakage. Lint failure is a result, not a crashing stack trace.

Pin a small versioned JSON rule-card schema rooted at exactly `schema_version`, `policy`, `defaults`, `facts`, `collections`, `rules`, `advice`. schema_version integer1 (not bool). Policy exact id/version/goal/source/scope/capabilities; identity/text nonempty strings, source exact document/version/section nonempty strings, capabilities unique nonempty strings. Defaults exact unknown/conflict/exemptions/migration values block/escalate/forbidden/explicit. Facts unique nonempty fact IDs. Collections exact id/version/completeness/allow_empty (three nonempty strings, last bool), unique IDs distinct from facts/rule IDs. Rules required exact id/source/modality/type/scope/trigger/depends_on/requirement/deadline/evidence/unknown/conflict/exemption/migration. Rules source same shape as policy source; modality must/forbidden, type state/action/history; explanatory strings nonempty; scope must name document or a declared collection; depends_on unique references to declared facts/collections/rule IDs; unknown block, conflict escalate, exemption forbidden, migration explicit. Evidence exact kind/source/subject/version all nonempty strings (declared provenance, not authenticated facts). Deadline either goal or one declared capability. Advice list of nonempty strings, kept separate and cannot become mandatory rules. Unknown fields rejected. Rules/facts/collections may be empty where meaningful, but at least one mandatory rule required for valid package. Cycle detection over rule-to-rule dependencies; undeclared references, duplicate IDs and deadline capabilities are diagnostics. No arbitrary expression evaluation or semantic natural-language consistency checking; lint-clean means structural review readiness only, not Runtime executable or published authority. `sop_digest` ties manual review to exact submitted content; this sprint does not implement authority approvals or immutable publication store.

Developer publishes valid expense/publishing rule-card examples and invalid bounded fixtures under `examples/sop/`, JSON only; dates/paths do not confer policy authority. CLI consumer later adds `lint-sop <path> --json` with stable JSON diagnostics, human display otherwise; exit0 clean/1 lint defects/2 malformed file or CLI usage. Duplicate JSON object keys must not be silently accepted by CLI loader. Linter API rejects invalid Python shapes; loader errors never output input contents/secrets. Clean CLI emits digest plus clear static-only limitation. Explain that textual predicates/source assertions still require a business publisher and engineered Policy implementation. Real external author feedback remains uncollected; independent Claude guide-only exercise is an agent rehearsal, not fabricated human validation.

## Filesystem third adapter

`work_runtime/file_adapter.py`: `FilePublisher(directory)` with actions content.publish, idempotency scope directory+key, lifetime-of-directory retention, lookup authoritative for committed by-key artifact, no additional document-content uniqueness promise (uniqueness empty tuple). Same Runtime/PubPolicy, different real side effect: actual immutable JSON artifact on local disk. No SQLite in adapter and no lifecycle edits.

Strict nonempty-string key and digest(document)==content_digest; document detached canonical JSON-native snapshot, malformed/mismatched input ValueError before any artifact. Hash key to a safe fixed basename; never use caller key/document.id as a path. Durable committed artifact includes original key, content digest, document and accepted receipt with stable nonempty external_id. `execute` samekey/samecontent returns identical receipt; samekey/differentcontent raises ValueError without overwriting; `lookup` missing returnsNone, malformed/corrupt artifact raises bounded ValueError (Runtime will retain unknown outcome), wrong-key/digest/result content is never accepted. Query reconstructs/validates artifact contents, including actual stored document digest, not just a receipt field.

Publish through atomic non-overwriting file creation using a staging file and exclusive commit (builder pins portable strategy). A crash before commit can leave only ignorable staging; after commit/query returns same receipt and exactly one committed artifact. Stage fsync before commit; declare directory sync/power-loss/platform boundaries honestly. Existing committed files never overwritten. Independent processes racing samekey must produce one committed artifact and stable result or documented retryable contention, no partial accepted file. Real conformance mixin adopter + restart/key-mismatch/corruption/path traversal/concurrent duplicate tests with actual filesystem enumeration and JSON contents. Single coordinator Runtime remains unchanged; adapter uniqueness does not imply distributed Runtime exactly-once or external fencing. Root directory trusted-local, no hostile filesystem/symlink security claim.

## D22 builder ratification — 2026-10-13

Independent reportfd8630c confirms implementability. Master choices before code:

- B1 facts are objects exactly `{id}`, all strings nonempty (whitespace-only invalid, content never trimmed). Global fact/collection/rule IDs unique; reserve collection id `document` as the business-document scope token. Root/cardinality otherwise exact draft.
- B2 proposal rejected: normative `policy.source.document` identifies institutional text, not the business object! Scope for policy/rules is literal `document` or a declared collection ID. Source fields remain declared provenance, neither existence nor authenticity verified. This keeps normative source and quantified business subject distinct.
- B3 accepted: reserve capability token `goal`; deadline literalgoal denotes goal boundary, otherwise declared capability. Unknown dependency/scope/deadline references diagnosed after valid ID collection. Both must AND forbidden rules are mandatory; all-forbidden package valid, empty rules gives NO_MANDATORY_RULE. Advice never becomes a rule.
- B4 accepted for ordinary supported/invalid Python values: lint returns diagnostics rather than shape/encoding/recursion exceptions; sop_digest raises bounded ValueError for non-clean. JSON-native preflight is iterative, depth<=64, no tuple/set/non-string dict keys/subclasses/custom object coercion, active-path identity detects cycles while repeated acyclic aliases remain valid, finite floats and abs(int)<=2^53-1, UTF-8-encodable strings/keys. This integer/Unicode restriction is a project interoperability bound, not a claim that RFC8259 bans escaped unpaired surrogates or large integers. Don't invoke user-defined repr/iteration hooks for errors. Invalid-native preflight errors can stop later schema cascade.
- Exactly14 diagnostic codes: MISSING_FIELD, UNKNOWN_FIELD, TYPE_MISMATCH, EMPTY_VALUE, INVALID_VALUE, DUPLICATE_ID, UNKNOWN_REFERENCE, CYCLE, NO_MANDATORY_RULE, NOT_JSON_NATIVE, NONFINITE_FLOAT, INVALID_UNICODE, INTEGER_RANGE, DEPTH_LIMIT (INVALID_SHAPE folded into TYPE_MISMATCH). Rootpointer empty, RFC6901 escape~0/~1, order(path,code,message), deduplicate identicaltriples. Identifier/enum snippets atmost64characters, no whole source/requirement/document values. Input object cycles use CYCLE with input-cycle message; dependency cycles report lowest document-index member and bounded IDnames. Duplicate ID/reference/capability all DUPLICATE_ID. No natural-language semantic consistency proof.
- Digest reuses policy.canonical/digest only AFTER clean preflight/schema, exact content sensitivity, object-key-order neutrality, no JCS/cross-language float guarantee. CLI loader rejects duplicateobjectkeys/nonfinite literals, unreadable/invalidUTF8/malformedJSON as exit2; syntactically valid escaped surrogate produces linter INVALID_UNICODE exit1, not a false RFCgrammar claim. Loader catches recursion without stacktrace and caps file1MiB; JSON defects output code/path/message, clean JSON output `{valid:true,digest:<sha>,diagnostics:[],scope:static-only}`, defective JSON output `{valid:false,digest:null,diagnostics:[...],scope:static-only}`. Human output explains static-only, exit0/1/2 as draft.
- FilePublisher artifact exact keys artifact_version/key/content_digest/document/receipt; strict artifact_version int1, original nonempty UTF8 key, snapshot canonical JSON-native document dict and recomputed digest matching receipt.digest; receipt accepted/nonempty external_id (FILE- plusuuid32 chosen once by winning staged commit), strictfields. Create ONE detached JSON snapshot, derive digest/persist from it, not multiple serialization passes over mutable caller data. File gate independent of authoring (parallel ownership), same native/depth/Unicode limits, bounded ValueError no raw payload leaks. Filename sha256(keyUTF8)+.json, no caller key/document.id inpaths. Committed bytes stable across replay; race staging files may differ in UUID, so do not claim deterministic precommit bytes.
- Atomic non-overwrite commit os.link(stage,final), same directory exclusive stage file ending .stage, fsync stage before link; FileExistsError reads/validates winner and samekey/content gets stable winningreceipt; differentcontent ValueError with no overwrite. Cleanup ownstage in finally on normalfailure/race. Best-effort directory fsync with documented supported-platform behavior; actual I/O failure may leave committed artifact and adaptercall uncertain, query resolves. Hardlink-unsupported volumes fail explicitly, no unsafe rename fallback. No power-loss or hostile/symlink FS guarantee.
- Reject production crash-exit constructor flags. API stays FilePublisher(directory); subprocess tests inject real process death beforecommit by wrapping os.link with os._exit, aftercommit by outer os._exit or Runtime.dispatch fault. Real artifacts are still written/fsynced; parent inspects actual files. Tests use subprocess races, restart, damagedartifact and mismatchedkey/digest; no timing/sleep-based race assertions. Query missingNone, corruption boundedValueError; unrelated staging ignored.
- Packaged example is the single truth source: authoring owner writes validJSON to work_runtime/data/sop/expense.json and publishing.json, invalid fixtures under examples/sop/; contributor guide links packaged examples. Harness owner adds pyproject package-data for data/sop/*.json and reads using importlib.resources.files(work_runtime), tested real noneditable install. No duplicate independent embedded example dicts or repo-cwd dependency. Foundation tests read sourcepackage data directly, installed harness verifies inclusion later. No hidden linking of linted cards to executing Python Policy.
- Guide path docs/contributor-guide.md, owned by dependent harness developer. Agent rehearsal is independent, docs/public interfaces only, fixtureeffects/tests and report; never claim real external human feedback. Installed adoption BOTH module/console count exactly1 committed hash-named file and independently parse actual artifact, key, actualdocument/receipt digest and succeeded Work binding; no output-only PASS.
