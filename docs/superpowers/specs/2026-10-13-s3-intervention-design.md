# S3 intervention design

## Intent and scope

Deliver a reproducible local intervention slice: stop future work without forgetting an external effect, transfer accountable ownership, and explicitly migrate a bound policy version. These are master's implementation choices under the user's standing autonomous-supervision instruction. Python >=3.9, SQLite, zero runtime dependencies, one dispatch coordinator remain. No network server, tenant authentication, compensation execution, evidence revocation, distributed leases or arbitrary cross-domain migration. The latter items remain deferred and must be labeled in the public roadmap/coverage.

## Cancellation

Add versioned, deduplicated commands `request_cancel` (payload exactly `reason`: nonempty string) and `finalize_cancel` (payload exactly `acknowledged_operations`: list of distinct nonempty operation IDs). Use the existing command protocol, durable receipts and event history.

Request persists cancellation intent/actor/reason, cancels waits and all never-dispatched prepared operations, and prohibits further proposal, re-admission, dispatch, document/plan edits or successful completion. Preserve original accepted command receipts; never relabel a prepared operation as externally confirmed_failed. Keep cancellation intent distinct from presentation status so verifier, expiry, malformed receipts and reconciliation cannot accidentally clear it. Repeated requests with a new ID cannot overwrite the original intent. Cancellation of an establishing work is supported. No automatic close: explicit finalize always records the terminal decision.

Unknown/dispatched operations remain queryable and reconcile through the original key. Missing lookup, malformed receipt, timeout and lookup exceptions leave cancellation unresolved. Finalize refuses every unresolved operation. Once resolved, finalize requires the exact set of confirmed-succeeded operation IDs; store their external IDs and all operation dispositions in the closure record. An empty list is correct only when there were no succeeded effects. Close as cancelled, never succeeded and never claim effect reversal. Request/finalize require current owner with work.manage or explicit local `work.intervene` administrator. Closed-work intake and immutable-history behavior must be documented and existing semantics preserved unless a tested safety need requires amendment.

## Responsibility

New Work stores owner=creator. Add `transfer_owner` with exactly `owner` and `reason`, both nonempty strings; target must exist in configured grants and possess work.manage. Current owner with work.manage or work.intervene administrator may transfer. Gate new management mutations by current ownership; propose_action also requires current owner plus existing capability, so a former owner's global grant does not retain this Work's execution rights. Evidence writers keep existing source-specific authority. Authorization must be rechecked before returning command replay; old owner must not replay protected management/action commands to bypass transfer. Receipt contents are never modified. Query APIs remain trusted-local.

Transfer persists before/after owner, reason and actor; reassign outstanding waiting/expired waits owned by the prior owner, invalidate prepared intents so new owner must re-propose, preserve in-flight operation actor/key/attempts/results and permit reconciliation. Dispatch also checks current Work owner, while reconciliation does not require old execution authority. Transfer remains possible during cancellation, cannot erase its intent, and does not grant capabilities. Same-owner transfer is rejected. Existing DBs lacking owner must remain readable: preserve legacy grant-only behavior until an explicit work.intervene administrator adopts ownership through transfer; do not guess an owner from historical receipt shapes.

## Policy migration

Add optional constructor policy registry of explicitly loaded versions in the SAME policy family and goal; default calls remain compatible. Default policy creates new works; every existing Work resolves its pinned binding from this registry (no implicit upgrade). Missing bound version still raises CommandError as today. Cross-domain policies are not a supported shared-database runtime. Validate registry identity/duplicates/family/goal before DB writes. Builder must pin exact constructor signature and registry validation contract before code.

Add `migrate_policy` command with exactly `policy_id`, `policy_version`, `reason`. Only work.intervene administrator, bound active work, no cancellation intent. Reject unchanged target, unregistered target, different family/goal, and any dispatched/unknown effect. Validate current document with target policy BEFORE mutation; evaluate evidence with target verifier rather than carrying verified authority blindly. Pending stays pending; previously invalid/revoked evidence must not resurrect. Previously verified evidence is downgraded/revalidated under target in the SAME transaction; accepted effect evidence remains authoritative only if target validates it and source matches target accepted source. Builder must settle exact evidence statuses and error codes before implementation. Increment contract revision, preserve plan/document history, cancel prepared intents/waits, evaluate target requirements and record old/new binding, actor/reason and evidence dispositions. Operation key identity must stay stable across same-family version migration; operation contract_revision must use actual revision rather than hardcoded1. Re-admission and dispatch must respect current contract revision. No hidden upgrade on constructor/restart/recovery. Old receipts and external results are retained. Transaction failures roll back binding, evidence, operations and events together.

## Ownership and waves

1. Independent builder check before implementation: scoped report, explicit blocking decisions; master ratifies in design/ADR.
2. ONE runtime developer owns runtime.py, any focused intervention helper module, tests/test_interventions.py, docs/interventions.md and runtime-boundaries.md SAME commit as runtime edits. Optional tiny policy protocol documentation changes only if required by settled design. Preserve all172 tests, no edits to existing test expectations or unrelated gateways/adapters.
3. Independent integration session merges foundation into carrier and reviews tests/RED/GREEN. Dependent demonstration worker owns intervention_demo.py, CLI, fresh installed verifier/CI smoke, tests/test_intervention_demo.py, READMEs/CONTRIBUTING/verification/public roadmap; separate scoped plan and report. No lifecycle code edits.
4. Independent integration owns accept, main merge, ordinary push and actual CI. Root never merges or pushes product work.

## Verification

Actual SQLite and real adapter counts, not mocked success. Test cancellation before dispatch (zero calls/effects), after timeout or real process death (query recovers one effect, explicit acknowledgement required), missing/malformed lookup (cannot finalize), stale versions, authority loss/replay, transfer with waiting and uncertain work, migration strengthened requirement and invalid prior approval, missing registry version, unchanged/cross-family target, in-flight refusal and atomic rollback, two works pinned to different versions in one family, reopen/recover without implicit migration. All configured gates plus existing installed demos pass; include deterministic no-credentials `intervention-demo`, installed outside checkout, exact effect-count assertions, policy-aware inspection and honest boundary docs. Every behavior change observed RED/GREEN, independent review, append-only acceptance before main merge; release complete only after non-force push/remote equality/actual CI.
